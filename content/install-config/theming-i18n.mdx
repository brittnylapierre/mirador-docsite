# Theming & i18n

Mirador uses Material UI for its interface foundations. Theme and language choices should be treated
as part of the installation, not a late-stage cosmetic pass.

Mirador theming usually happens at three levels: override a palette key, override a specific Material
UI component, or register an entirely new theme.

## Select A Theme

```js
Mirador.viewer({
  id: "mirador",
  selectedTheme: "dark",
});
```

## Customize Palette Colors

```js
Mirador.viewer({
  id: "mirador",
  themes: {
    light: {
      palette: {
        primary: {
          main: "rgb(25, 103, 210)",
        },
        secondary: {
          main: "rgb(25, 103, 210)",
        },
      },
    },
  },
});
```

## Override A Specific Component

Use `theme.overrides` when one Material UI component needs a targeted style change. Floating action
buttons are a useful small example.

```js
Mirador.viewer({
  id: "mirador-viewer",
  theme: {
    overrides: {
      MuiFab: {
        primary: {
          backgroundColor: "yellow",
          color: "black",
        },
      },
    },
  },
});
```

## Register A New Theme

Add a named theme under `themes` when you want users to choose it from the workspace theme menu.

```js
Mirador.viewer({
  id: "mirador-viewer",
  themes: {
    readingRoom: {
      palette: {
        type: "dark",
        primary: { main: "rgb(25, 103, 210)" },
        secondary: { main: "rgb(25, 103, 210)" },
        shades: {
          dark: "#000000",
          main: "#424242",
          light: "#616161",
        },
      },
      typography: {},
    },
  },
  selectedTheme: "readingRoom",
});
```

## Override Existing Translation Text

Use `translations` when you need to change copy in a configured language.

```js
Mirador.viewer({
  id: "mirador",
  translations: {
    en: {
      downloadExportWorkspace: "Download workspace settings",
    },
  },
});
```

Find keys in the locale translation files, then override only the copy you need for your
installation.

## Language Defaults

Use `language` to choose the default interface language. Use `availableLanguages` to control which
languages appear in the language switcher.

```js
Mirador.viewer({
  id: "mirador",
  language: "en",
  availableLanguages: {
    en: "English",
    fr: "Français",
    ja: "日本語",
    "pt-BR": "Português do Brasil",
  },
  window: {
    showLocalePicker: true,
  },
});
```

## Add A Language

Adding a new language requires a locale directory, a translated `translation.json`, and registration
in Mirador’s i18n resources. Plugin authors should use the translation hooks re-exported by Mirador.

## The Two Interacting Language Systems

Mirador handles internationalization through two distinct, interacting language layers built on `i18next`:

1. **App Interface Language (`locale` / Workspace Settings):**
   - Configured via initialization settings (`language: 'en'`) or selected by users via the **⚙ settings** menu.
   - Controls Mirador's own user interface elements: buttons, menus, dialogs, and companion sidebar headers.
2. **Manifest Metadata Language:**
   - Provided inside the IIIF manifest when publishers supply multilingual metadata strings or annotation labels.
   - When a manifest offers multiple language translations, an in-window dropdown allows users to switch metadata language.
   - **Automatic Alignment:** If a user selects an app interface language that the loaded manifest also provides, Mirador automatically switches the manifest metadata language to match.

> [!WARNING]
> **Known Issue — Language State Alignment**:
> Redux state alignment between the global app language and the per-window manifest language can occasionally suffer from stale-state synchronization in complex multi-window workspaces.

## Right-To-Left (RTL) Layout vs. Viewing Direction

When deploying Mirador in Arabic, Hebrew, Persian, or other right-to-left language contexts, implementers must distinguish between **UI layout direction** and **content viewing direction**:

- **Interface Direction (RTL Layout):**
  Mirador's Material UI interface fully supports RTL flipping. When an RTL language is active, the entire application layout flips horizontally: the workspace control bar, window sidebars, companion panels, toolbars, and thumbnail strips invert their orientation.
- **Viewing Direction (Resource Data):**
  Independent of the UI layout, a manifest's declared `viewingDirection` (`left-to-right`, `right-to-left`, `top-to-bottom`, `bottom-to-top`) controls page navigation arrows, thumbnail scroll axes, and facing-page layouts in Book view.
  A user viewing an Arabic manuscript in an English-language UI will still receive correct right-to-left page turning and thumbnail sequencing.
