# Working with Annotations

In the IIIF ecosystem, annotations are first-class citizens. Annotations link commentary, scholarly transcriptions, translations, visual highlights, and tags to specific canvases or spatial coordinate regions (`xywh` rectangular fragments or SVG polygons).

Mirador renders annotations seamlessly over the image canvas while providing a structured list in the companion sidebar.

![Sidebar Annotations Panel](/img/user-guide/sidebar-annotations.png)

---

## Viewing Canvas Annotations

When a loaded manifest includes linked `AnnotationList` (Presentation v2) or `AnnotationPage` (Presentation v3) resources:

1. Click the **Toggle sidebar** button (`☰`) in the window header.
2. Select the **Annotations** tab (speech bubble icon).
3. The Annotations panel lists all annotations associated with the active canvas.

> [!TIP]
> **The Orange Indicator Dot**:
> - An **orange dot** on the Annotations tab icon indicates that annotations have successfully loaded for the page you are currently viewing.
> - If the tab icon appears **without an orange dot**, the item may contain annotations elsewhere in the manifest, but none are present or currently fetched for the active canvas.

## Anatomy of an Annotation in Mirador

Mirador supports standard W3C Web Annotation and Open Annotation data models:

- **Target / Spatial Selector**: A rectangular fragment (`#xywh=100,200,300,150`) or complex SVG path defining where the annotation appears on the canvas.
- **Body / Content**: The textual transcription, translation, explanatory comment, or HTML-formatted note.
- **Motivation**: Identifies the purpose of the annotation (e.g., `commenting`, `supplementing`, `tagging`, `describing`).
- **Creator / Attribution**: Metadata identifying who created the annotation and when it was authored.

---

## Interacting with Annotations on the Canvas

- **Canvas Overlays**: Bounding boxes or shaded SVG polygons are drawn directly over the image canvas.
- **Hover & Tooltip**: Hovering your cursor over an annotated region highlights the corresponding text in the sidebar.
- **Click to Focus**: Clicking an annotation in the sidebar zooms the canvas directly to that region and displays the commentary card.
- **Toggle Visibility**: Use the visibility toggle icon in the Annotations panel header to hide or show annotation bounding boxes on the canvas, allowing unobstructed inspection of the underlying image.

## Annotation Collections & Pagination Handling

Institutions often publish annotations grouped into `AnnotationCollection` resources or across paginated `AnnotationPage` records:

| Feature | Status | Behavior in Mirador |
| :--- | :--- | :--- |
| **Annotation Display** | ✅ Supported | Rectangles, polygon fragments, and SVG selectors render accurately over the canvas. |
| **Annotation Collections** | ⚠️ Partial | Linked `AnnotationCollection` pages load, but collection-level labels are not displayed in the sidebar—annotations are **flattened** into a single continuous list. Paginated multi-page collections are not fully navigated ([GitHub Issue #589](https://github.com/ProjectMirador/mirador/issues/589)). |
| **Annotation Authoring** | ❌ Not in core | In-viewer drawing, tagging, and creating new annotations is not part of Mirador 4 core. |

> [!NOTE]
> **HTML Sanitization**: To protect users from cross-site scripting (XSS), Mirador automatically sanitizes HTML content inside annotation bodies using DOMPurify. Raw `<script>` tags, dangerous `<iframe>` elements, or inline event handlers (`onclick`) are stripped prior to display.

## Creating Annotations (Authoring Plugins)

Mirador core is purposefully focused on **rendering, inspecting, and navigating** annotations rather than authoring them:

- In Mirador 2 and 3, interactive annotation authoring was enabled by the community-developed `mirador-annotations` plugin.
- The `mirador-annotations` plugin was not maintained through the Mirador 4 upgrade.
- If your project requires annotation authoring (e.g., drawing bounding boxes, submitting transcriptions to a backend like SimpleAnnotationServer or Elucidate), you will need to build or adapt a custom plugin using Mirador's Redux action and plugin architecture.
- For reference on creating custom plugins, see the [Plugins Guide](/install-config/plugins) and the [Mirador IIIF Support Matrix](/iiif-support).
